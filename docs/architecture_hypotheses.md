# Архитектурные гипотезы после заявки 58090521

Проверенный результат нового файла: Kaggle MSE **2 068 464.49379**, локальный
MSE **1 893 853.23917** на 468/597 строках. Прежний лучший Kaggle MSE —
**1 967 765.75828**. Новый файл хуже на public на 5.12%; основной артефакт сохранён.
Малые изменения XGBoost не дали устойчивого улучшения. Ниже — предложения,
не обученные модели; их Score и величина возможного выигрыша пока неизвестны.

## 1. Предобученный графовый энкодер CheMeleon и совместные головы

SMILES → граф атомов/связей → предобученный D-MPNN → общий вектор → головы
log(IC50), log(CC50). Вместо фиксированного Morgan сеть использует обученное
представление химической структуры. Пропуски маскируются независимо; концентрации
из условных SI не восстанавливаются.

Первый опыт: замороженный энкодер с небольшими регуляризованными головами.
Второй: осторожное дообучение энкодера. Контроль — тот же D-MPNN со случайными
весами, одинаковые данные и разбиения. Это отделяет пользу предобучения от
простой смены названия модели. Основной риск — переобучение малого набора.

Chemprop предоставляет загрузку CheMeleon, замораживание и fine-tuning:
[официальный пример](https://chemprop.readthedocs.io/en/latest/chemeleon_foundation_finetuning.html),
[multitask-модель](https://chemprop.readthedocs.io/en/latest/multi_task.html).
Это мой первый приоритет: меняются и представление молекулы, и обмен информацией
между головами, а предобучение уменьшает необходимость учить химию с нуля.

## 2. Совместная вероятностная модель IC50/CC50

Проверить multi-output Gaussian process с Tanimoto-ядром и корреляцией двух
лог-концентраций. Обучать на независимо доступных целях. Такая модель учится
по всей ковариационной матрице; ранее проверенная поправка по пяти соседям
не проверяет эту гипотезу.

Прогнозировать распределение log(SI), затем его среднее в исходной шкале для
raw MSE. Для совместно нормальных натуральных логарифмов предлагаемый прогноз:
`exp(mu_CC - mu_IC + 0.5*(var_CC + var_IC - 2*cov_CC_IC))`.
Это модельное допущение; неопределённость требуется проверять на обучающих OOF.
Чрезмерная дисперсия способна резко завысить SI, поэтому рядом нужен контроль
без вероятностной поправки. Глобальный множитель из тестовых ошибок не подходит.

Основа для GP на небольших молекулярных данных:
[FlowMO, первичная публикация](https://arxiv.org/abs/2010.01118).
Совместное распределение и его применение к нашим двум целям — предлагаемое
расширение, а не заявленный результат этой публикации.

## 3. Предобученный 3D-трансформер Uni-Mol

SMILES → конформеры RDKit → предобученный 3D-энкодер → небольшие головы концентраций.
Это добавляет геометрию, отсутствующую в текущем Morgan. Сначала проверить
замороженные embeddings; затем fine-tuning, если первый этап полезен.
Контроль — одинаковые головы на 2D- и 3D-представлениях.

Риски: ошибки конформеров, гибкость молекул, стоимость вычислений; геометрия
не гарантирует объяснения биологической активности. Все строки должны получить
прогноз, включая неудачные генерации конформеров, по заранее заданному fallback.
[Официальный репозиторий Uni-Mol](https://github.com/deepmodeling/Uni-Mol).

## 4. Общая химия, отдельные головы для источников данных

Общий предобученный энкодер → отдельные головы public/Kaggle для каждой
концентрации. Публичные данные обучают общую часть и свою голову; точные данные
соревнования — голову целевого домена. На инференсе всегда используется ветвь
Kaggle, входом остаётся только SMILES. Cell line и тестовые концентрации не нужны.

Мотивация — ухудшение после простого объединения дополнительных измерений.
Различия условий и качества являются возможной причиной, но ещё не доказаны.
Контроли: Kaggle-only, общая голова на объединении и отдельные доменные головы.
Это гипотеза переноса принципа multitask на источники биологических измерений;
публикация о неоднородных молекулярных данных демонстрирует принцип в другой
задаче: [Fisher et al., 2024](https://arxiv.org/abs/2401.17898).

## Что уже известно и как сравнивать

В API обнаружена другая завершённая заявка `submission_dmpnn_arch4_new_dataset.csv`,
58089542, public MSE **12 173 494.68064**. Её код, данные и артефакт в текущем
checkout отсутствуют; по имени файла нельзя достоверно установить архитектуру.
Перед повторением D-MPNN нужно сопоставить её реализацию с предложением 1.

Каждый новый кандидат сравнивается на прежних molecule/scaffold OOF с masked
целями, фиксированным holdout и отдельными метриками измеренных/условных/низких SI.
Итоговая таблица всегда содержит OOF Score, локальный Score с покрытием и
официальный Kaggle Score при наличии. Тестовые endpoints читаются только после
инференса; выбор параметров по ним не выполняется. Для новых заявок требуется
новое указание пользователя: текущее разрешение использовано для 58090521.

Практический порядок: CheMeleon → совместный GP → Uni-Mol. Доменные головы
проверить как отдельную абляцию CheMeleon. Обещать конкретный процент или топ-5
до экспериментов оснований нет.
