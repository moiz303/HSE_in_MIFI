# Локальный score для вариантов 1, 2 и 3

## Формула

API Kaggle для `molecular-activity-prediction-hack` подтверждает метрику
`Mean Squared Error` (проверено 7 ноября 2026, новых заявок не отправлялось).

`local_score = mean((SI_pred − SI_original_Kaggle)²)`.

Меньше — лучше. Считаются исходные единицы SI без логарифмирования, обрезки цели,
весов оценочных строк или исключения SI=10000. Повторы исходного train.csv
сохраняются отдельными строками. Нулевые цели допустимы; некорректные числа
вызывают ошибку. MSE ChEMBL не включается в основной score.

Дополнительно выводится `skill_vs_constant = 1 − MSE_model / MSE_constant`.
Константа — среднее исходных SI Kaggle **только обучающей части текущего fold**.
Положительный skill означает выигрыш над константой, отрицательный — проигрыш.
Это вспомогательное нормирование, а не метрика Kaggle.

## Проверочные выборки

В пул входят только существующие train+validation: 1007 структур, соответствующие
267 исходным строкам Kaggle. Holdout не используется и не оценивается. Исходные
метки берутся из `data/processed/kaggle_reference.csv`, а не из смешанных агрегатов.
Обучающие концентрации остаются такими же, как у вариантов 1/2: меняется только
взвешивание варианта 3. Это позволяет отделить эффект весов от новой очистки целей.

Два протокола, каждый по 3 fold и 3 повторения с фиксированными seed:

- `molecule`: перемешивание по стандартизированным молекулам. Одинаковая структура
  целиком находится в одной части; сходные каркасы могут быть в разных частях.
  Это приближение к случайному разделению соединений, а не установленная схема Kaggle.
- `scaffold`: целые каркасы Мурко остаются в одной части, включая публичные структуры.
  Ациклические структуры тоже группируются вместе. Это более строгая проверка переноса.

Для каждого fold заново обучаются: пять пар XGBoost (вариант 2) и одна взвешенная
пара (вариант 3). Вариант 1 — первый участник ансамбля с исходным seed, поэтому
сравнение не зависит от случайного различия двух отдельных обучений baseline.
Ни одна модель не прогнозирует для score строки, на которых она обучалась.

## Как читать результаты

- Основной MSE — средняя квадратичная ошибка по всем OOF-прогнозам исходных строк
  и повторениям. Каждая исходная строка оценивается один раз за повторение.
- `repeat_mse` и его стандартное отклонение показывают чувствительность к разбиению.
  Результаты повторений перекрываются и не являются независимыми выборками.
- `paired_gain_vs_variant1` — MSE варианта 1 минус MSE кандидата. Положительное
  значение означает улучшение. 95% интервал получен парным bootstrap по scaffold;
  перед bootstrap потери повторений усредняются для каждой исходной строки.
- Отдельные группы: условные метки, измеренный SI, SI<1000, SI>=10000. Они нужны,
  чтобы видеть обмен ошибками; результаты выбранной по истинной цели группы
  нельзя выдавать за score всего теста.
- RMSE, MAE и ошибка логарифма — дополнительные показатели. Первичным остаётся MSE.

Ни один локальный score не гарантирует совпадения с числом Kaggle: его скрытые
строки, распределение и публичная подвыборка неизвестны. Если два протокола дают
разных победителей или интервалы широкие, вывод о превосходстве неустойчив.
Три кандидата сравниваются исследовательски: автоматической замены проверенной
модели или отправки на Kaggle нет. Holdout по-прежнему зарезервирован.

## Запуск и файлы

На Mac: `python -m src.local_compare --config configs/xgb_weighted.json`.
Онлайн-доступ и тестовый CSV не нужны. Новое `./run_mac.sh` сначала выполняет
это сравнение, затем финально обучает вариант 3 и создаёт его submission при наличии теста.

- `reports/local_comparison.csv` — краткая таблица вариантов по обоим протоколам;
- `reports/local_comparison.json` — метрики, интервалы, seed, версии, SHA256 входов;
- `reports/local_comparison_oof.csv` — исходная цель и все прогнозы каждой строки/fold;
- `reports/local_comparison_splits.json` — воспроизводимые индексы всех разбиений.

Стандартный запуск сравнения — 18 fold-задач, 216 регрессоров по 400 деревьев
(вариант 1 переиспользуется из ансамбля). Это значительно дольше одиночного
обучения. Для короткой проверки можно сделать отдельную конфигурацию с
`local_comparison.repeats=1`; сравнивать следует результаты одного и того же протокола.
Прежние финальные артефакты не переобучаются и не перезаписываются этим сравнением.
