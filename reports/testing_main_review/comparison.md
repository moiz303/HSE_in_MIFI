Проверена ветка `origin/testing_main`, коммит `92aedefeaeeb4546c7a714a78720563c7f1fa35a`.
Модель: один CatBoostRegressor, RMSE по исходному SI, 600 деревьев, depth5,
learning_rate0.03; Morgan2048 + 13 дескрипторов. ChEMBL не используется.
Ни одна заявка на Kaggle не отправлялась. Лучшая подтверждённая модель сохранена.

на этой проверке; официального результата нового CatBoost нет.

## Почему validation 352196.79 не означает Kaggle 352196.79

Внутреннее разбиение: 214 train / 53 validation внутри development267,
seed20261106, Murcko scaffold. Исходный validation MSE: **352196.79101**;
после ограничения прогнозов нулём: **352125.82301**.
На том же разбиении константа со средним только fit-части даёт **87560.45668**,
а фиксированный ноль — **22066.21377**. CatBoost не обошёл эти простые ориентиры.
Максимальный SI в validation — **800**, в fit — **36066.667**; в validation15 нулей.
Одно разбиение не проверяет устойчивость по редкому хвосту. Повторный OOF этого
CatBoost не выполнялся; нельзя приписывать ему сравнение на прежних 18 фолдах.

Глобальный резерв: 53 исходные конкурсные строки исключены из обучения и оценки.
Это другие 53 строки, чем внутренняя validation. Исходный запуск ветки на всех
320 строках намеренно не выполнялся, поскольку поглотил бы этот резерв.

## Главная находка: устаревшие обучающие цели

Официальный файл `train_v2.csv` скачан отдельным read-only запросом Kaggle.
SHA256: `d9a876a67b5623d9cdb6592fc53d31ffaa7c535b09968c3a538138740fe246e8`.
По сравнению с сохранённым `train.csv` изменены ровно 81 значения: 10000 → 0.
Остальные колонки, структуры и порядок строк полностью совпадают.
В development267 изменены 66 целей; новая модель сохранила все 66 нулей.
Во всём train_v2 — 83 нулевых цели, включая два прежних нуля в резерве.

Загрузчик исправлен: `load('train')` требует `train_v2.csv`, без скрытого отката
на старый train. Старый ZIP-кэш больше не мешает отдельно получить train_v2.
Проверка условных SI допускает ноль, агрегация SI с нулями использует медиану
в исходной шкале; положительные концентрации по-прежнему агрегируются в логах.
Для смеси нулевых и положительных SI логарифмический разброс не объявляется.
Исторические processed-таблицы и обученные модели не перезаписаны. Они остаются
снимками старого датасета; новый экспорт/OOF требует отдельной версии данных.
Исторические оценки Kaggle действительны, но старый OOF по условной цели10000
не соответствует актуальному train_v2. Прежний sentinel_cal с уровнем10000
нельзя возобновлять как актуальную гипотезу.

## Сильные стороны

- Только конкурсные данные: исключён сдвиг assay и источников ChEMBL.
- Актуальные SI-цели, нули сохраняются; loss соответствует сырому MSE.
- Строгая проверка ID, порядка шаблона и входов; тестовые endpoints не участвуют.
- Простой воспроизводимый CPU-baseline, нативный переносимый CBM-артефакт.

## Слабые стороны

- Всего267 development-строк и один split; нет оценки устойчивости по повторным фолдам.
- Большой хвост сырого SI перетягивает RMSE; текущая модель хуже констант на своём split.
- Исходный код допускает отрицательные SI: 22/597 на v2 (минимум −91.70),
  72/597 на старых целях (минимум −794.77). Нулевая граница — явная поправка при диагностике.
- README ветки указывает несуществующий модуль `baseline_catboost.run`;
  рабочая команда — `python -m baseline.run`.
- Это проверка совокупности изменений, а не доказательство, что исключение
  ChEMBL само по себе улучшает модель. Для такого вывода нужна контролируемая абляция.

## Воспроизведение и проверки

Создать отдельный worktree на указанном коммите. Скачать официальный train_v2,
оставить строки, чьи standard_smiles входят в прежние train+validation; записать
временный CSV только с SMILES и SI VACV. Для теста записать index+SMILES.
Внутри worktree запустить:

```powershell
python -m baseline.run --train ../HSE_in_MIFI/logs/testing_main_inputs/train_v2_development.csv --test ../HSE_in_MIFI/logs/testing_main_inputs/test_smiles.csv --sample ../HSE_in_MIFI/data/raw/kaggle/sample_submit.csv --expected-train-rows 267 --output-dir ../HSE_in_MIFI/artifacts/testing_main_review/v2_development
```

Артефакт: `artifacts/testing_main_review/v2_development/catboost_si_vacv.cbm`.
В новом процессе обе модели загружены и воспроизвели исходные прогнозы всех597 ID.
9 тестов ветки прошли. Исправления загрузки/нулей покрыты тестами main;
точный результат полного прогона — `main_tests.log`.
